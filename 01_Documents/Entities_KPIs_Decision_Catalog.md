# Foresight — Entities, KPIs & Decision Catalog

**Status:** Locked for MVP (Week 1 deliverable). Changing this later is a real decision,
not a casual edit — update this file and note why if it changes.

## 1. Dataset Decision (Locked)

**Real backbone:** DataCo Smart Supply Chain Dataset (Kaggle) — real, widely-used
industry order/shipping dataset. ~180,000 orders, ~30,000 customers, ~10,000 products,
with genuine `days for shipping (scheduled)` vs `days for shipping (real)` fields.

**Synthetic extension (clearly labeled, never presented as real):** DataCo has no
supplier or inventory-level data, so a supplier and inventory layer is generated on
top of it — supplier identities, lead-time histories, and stock-on-hand snapshots —
built to be internally consistent with DataCo's real order volumes and product
categories. Every synthetic field is documented here and tagged in the schema so
nobody, including us months from now, mistakes it for real-world data.

**Why this combination:** it gives a genuine, citable real dataset as the credibility
anchor, while guaranteeing the exact signal (a supplier's lead time drifting toward a
stockout) actually exists cleanly enough to build and demo a full detect → explain →
recommend → outcome loop. See blueprint §21 (Risk: Fake-looking data) — this is the
documented, transparent approach that section calls for, not a shortcut around it.

## 2. Decision Workflow (Locked)

**The one decision this MVP proves:** *Is a supplier's slowing performance about to
cause a stockout, and if so, what should the operations manager do about it?*

This is the running example used throughout the blueprint and proposal (the furniture
frame supplier). It is the only decision workflow built for the MVP — no other
signal type ships until this one is proven end-to-end.

## 3. Entities

| Entity | Source | Key fields |
|---|---|---|
| `order` | DataCo (real) | order_id, order_date, customer_id, product_id, quantity, order_status, shipping_mode, days_for_shipping_scheduled, days_for_shipping_actual |
| `product` | DataCo (real) | product_id, category, price, unit_cost |
| `customer` | DataCo (real) | customer_id, segment, region — retained for context, not central to the MVP decision |
| `supplier` | **Synthetic** | supplier_id, name, region, category_supplied |
| `supplier_delivery` | **Synthetic** | supplier_id, product_category, expected_lead_time_days, actual_lead_time_days, delivery_date |
| `inventory_snapshot` | **Synthetic**, demand derived from real DataCo order volume | product_id, snapshot_date, stock_on_hand, safety_stock_level, avg_daily_demand |
| `signal` | Generated by the system | signal_id, entity_type, entity_id, metric, baseline_value, observed_value, deviation, detected_at |
| `decision` | Generated by the system | decision_id, signal_id, action_type, evidence, confidence, status, owner_role, created_at, resolved_at, outcome |

## 4. KPIs (baseline formulas — advanced versions come later, never replacing the baseline)

| KPI | Baseline formula | Used for |
|---|---|---|
| Supplier On-Time Rate | on-time deliveries ÷ total deliveries (rolling 30/60/90-day window) | Supplier health |
| Supplier Lead Time Drift | rolling average actual lead time vs. historical baseline (z-score/IQR) | Anomaly detection |
| Days of Stock Remaining | stock_on_hand ÷ avg_daily_demand | Stockout risk |
| Stockout Risk Score | combines Days of Stock Remaining against incoming expected lead time + a demand-volatility buffer | Prioritization |
| Order Fulfillment Delay Rate | late shipments ÷ total shipments (from DataCo's real scheduled-vs-actual fields) | Cross-check / secondary signal |
| Demand Deviation | actual demand vs. seasonal-naive baseline | Forecast sanity check |

## 5. Decision Catalog (the only actions the system can ever recommend, for MVP)

| # | Action | Triggered when | Owner |
|---|---|---|---|
| 1 | **Reorder now** | Days of Stock Remaining < expected incoming lead time + safety buffer | Ops manager |
| 2 | **Escalate supplier** | Supplier Lead Time Drift exceeds threshold for 3+ consecutive periods | Ops manager / procurement |
| 3 | **Shift to backup supplier** | Escalation was raised and drift continued worsening afterward | Ops manager |
| 4 | **Review demand forecast** | Demand Deviation is high enough that stock projections are no longer trustworthy | Ops / planning |
| 5 | **Monitor (no action)** | Signal exists but confidence is below threshold | System — no human action required yet |

Every decision the system ever proposes must map to exactly one row in this table.
If a future signal doesn't fit one of these five, it's a sign the catalog needs a
deliberate update — not that the system should invent a new action ad hoc.

## 6. What Is Explicitly Not in Scope Yet

- Any signal type other than supplier-lead-time-to-stockout (pricing, demand shocks,
  SLA breaches — all in the blueprint's future roadmap, not this MVP).
- Any entity beyond the eight above.
- Any decision beyond the five in the catalog.
